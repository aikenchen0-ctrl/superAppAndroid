1. 外部需求文档读取结论

可以看到大致需求描述。Google Docs 页面本身需要 JS/权限渲染，但导出文本链接可以读取正文。文档核心关键词如下：

产品框架IM 悬浮页、双侧悬浮中台、视频页、商城页、浏览器、知识库页、AIfx 模板编排、自身帐号、朋友圈、搜索、通讯录关系、AI 特殊状态。
消息气泡AI 友好消息格式，位置、名片、小程序、链接、文件预览、文本混排、图片缩略图、引用、权限申请。
交互体系轻触/重触区分、闭眼触发、边缘拉动、拖拽、摇杆/套索/旋钮、倾斜二维码、任意页面 AI 唤醒。
模块化方向aispect、灵动岛、PIP、悬浮 IM、聚合 IM 数据模型、多维视频、AI 文本框、todo、知识库、AI 浏览器、AI 云盘。

本次同步：已新增 6 个物理模块目录和模块注册表；消息气泡改为真实 Auto Layout 拟合高度；左侧会话去重和绑定改为 UUID；直接会话帐号归属增加稳定解析器；新增“智能扣图”工具，默认关闭，开启后对新拍摄/新选择图片使用设备端 Vision 生成透明 PNG。当前仍以本地模拟和 UIKit 原型为主，尚未接入真实后端数据。

当前验收口径

  • 已完成原型：真机可打开、主要交互可跑通、UI 可展示，数据可为本地模拟。
  • 已完成业务原型：除 UI 外，已接入当前 App 状态或 SQLite/内存状态，能随主流程变化更新。
  • 部分完成：有页面或关键交互，但缺真实服务、统一数据模型、稳定 SDK、跨页面复用或异常处理。
  • 缺失：没有可进入的页面或只有零散入口，无法按需求形成闭环。
  • 生产级验收：必须包含真实 API/权限/分页/错误处理/持久化/真机稳定性/自动化或手工验收用例。

本轮“已完成”以源码、Debug 编译和现有本地状态闭环为依据；涉及相机、相册、Vision、眨眼、灵动岛、后台行为的项仍需单独真机验收。

5. SQLite 数据模型缺口

当前 SQLite 已有 messages、attachments、message_attachments、app_state、accounts_cache、contacts_cache、conversations、conversation_members、message_status。这对本地 IM 原型足够，但不够支撑文档中的完整产品。

建议新增表/模型 原因 关键字段
account_contacts / conversation_owners 右侧帐号筛选左侧好友和直接会话归属目前已有稳定解析，但还不是可编辑、可同步、可查询的持久化关系。 account_id, contact_id, conversation_id, ownership_source, created_at, updated_at
group_members（关系增强） 已有 conversation_members 基础表，但群成员展示、移除成员、多个帐号在群中的成员资格仍有内存/消息推断路径。 group_id, member_id, member_role, group_nickname, joined_at, removed_at, visible_flags

moments_posts / comments / reactions 朋友圈目前是本地数组，不可持久化完整动态。 post_id, owner_id, media_json, comment_id, parent_id, reaction_type
