# 悬浮聊天性能优化实施计划

> **执行要求：** 使用测试驱动开发逐项实施；每项先取得预期红灯，再做最小生产修改。共享工作区已有消息渲染、媒体和 SCRM 改动，禁止覆盖或回退。

**目标：** 在业务、接口、消息渲染和 UI 像素不变的前提下，消除未读总览的重复全量扫描与二次分组，并降低连接线每帧分配，通过真机固定手势证明改善。

**架构：** 保持现有 Compose 树、Lazy 列表、坐标精度和几何规则，仅优化纯派生计算、不可达工作和 draw 阶段对象生命周期。所有缓存均以完整业务输入为 key，不引入过期数据。

**技术栈：** Kotlin、Jetpack Compose、JUnit4、Gradle、ADB `gfxinfo`。
