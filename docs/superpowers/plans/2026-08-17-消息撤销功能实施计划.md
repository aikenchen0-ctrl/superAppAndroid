# 悬浮聊天消息撤销功能实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为已同步的本人消息增加“撤销”操作、二次确认和真实 SCRM 撤回任务，并在任务明确成功后刷新消息所属会话。

**Architecture:** 消息菜单只负责展示和发出撤销意图，`MessageInteractionOverlayHost` 承载确认对话框，`FloatingChatOverlayUi` 负责账号路由、并发控制、异步任务和会话刷新。新增一个小型 `ScrmMessageRevokeTaskRunner` 复用现有 `ScrmContactTaskRunner` 的任务轮询，避免在 Compose 宿主中复制轮询逻辑。

**Tech Stack:** Kotlin 2.x、Jetpack Compose Material 3、Kotlin Coroutines、JUnit 4、Robolectric、Gradle。

- [ ] **Step 3: 实现最小任务适配器**

新增：

```kotlin
internal class ScrmMessageRevokeTaskRunner(
    private val messageApi: ScrmMessageOperationApi,
    private val taskApi: ScrmTaskApi
) {
    fun revokeAndAwait(
        remoteMessageId: Long,
        deviceUuid: String,
        weChatId: String
    ): ScrmContactTaskOutcome {
        require(remoteMessageId > 0L) { "remoteMessageId 必须大于 0" }
        require(deviceUuid.isNotBlank()) { "deviceUuid 不能为空" }
        require(weChatId.isNotBlank()) { "weChatId 不能为空" }
        return ScrmContactTaskRunner(taskApi).submitAndAwait(reloadContactsOnSuccess = false) {
            messageApi.revokeMessage(
                remoteMessageId,
                ScrmMessageOperationRequest(deviceUuid = deviceUuid, weChatId = weChatId)
            )
        }
    }
}
```
