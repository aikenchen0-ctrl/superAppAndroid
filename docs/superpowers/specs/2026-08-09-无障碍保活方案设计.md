# 无障碍保活方案设计

## 目标

在主设置页提供“无障碍保活”开关。开启后，应用每次启动都尝试恢复本应用无障碍服务：优先使用 ROOT；无 ROOT 时使用已配对的 ADB shell 通道。用户可以在独立教程页完成 ADB 配置并复制与当前应用包名匹配的命令。

## 架构

- `:app`：开关、教程 Activity、Application 初始化。
- `:ubiki-accessibility`：共享偏好和无障碍服务组件名生成，不负责提权。
- `:adbcore`：从 AdbKeeper 合并的 ADB wireless debugging 核心库。
- `AccessibilityKeepAliveController`：在 app 层协调 ROOT/ADB/状态校验，所有 shell 执行均异步并返回明确结果。

## 数据流

开关写入 `UbikiPreferences`。`MainActivity.onResume` 和开关打开事件调用 controller；controller 检测 ROOT，ROOT 成功则执行 `settings put secure`，否则检查 ADB 是否已配对并执行同一组 shell 命令。命令使用 `ComponentName(context, UbikiAccessibilityService::class.java)` 动态生成，保留已有服务并追加当前服务。

## UI

教程页显示实际包名、服务组件名、复制按钮、ROOT/ADB 原理、首次配置步骤和验证命令。ADB 方案明确说明 Android 11+ 无线调试配对、撤销授权和 ROM 限制；复制命令不包含任何示例包名。

## 错误处理与测试

ROOT、ADB 和设置写入失败均返回带原因的结果并在 UI 中提示，不静默伪造成功。纯 Kotlin 测试覆盖服务列表合并、命令生成和执行路径选择；构建验证覆盖 `:app:assembleDebug` 与相关单元测试。
