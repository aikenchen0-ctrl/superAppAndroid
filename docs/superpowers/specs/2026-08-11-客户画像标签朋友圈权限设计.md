# 客户画像、标签与朋友圈权限设计

> 日期：2026-08-11  
> 状态：待用户最终审阅  
> 范围：Android 悬浮聊天 SCRM，单联系人详情页  
> 选定方向：方案 A，联系人详情内聚合

## 1. 目标

将当前“只能读取和组装请求”的联系人资料页升级为可维护、可确认、可回读的单联系人业务闭环：

- 编辑 SCRM 客户画像，保存后重新读取并逐字段核对。
- 从账号标签字典选择联系人标签，明确完整替换语义，任务成功后回读详情。
- 设置三项朋友圈权限，任务成功后回读真实权限状态。
- 网络、任务、回读或字段不一致时明确失败，不显示假成功，不丢失用户草稿。

首版不包含批量标签、按筛选打标、批量朋友圈权限、标签字典创建/删除。这些能力继续保留在 SCRM 运营工作台。

## 2. 用户入口与信息架构

入口保持不变：悬浮聊天 -> 联系人 -> 选择联系人 -> 联系人详情。

联系人详情按以下顺序使用全宽信息区，不使用卡片嵌套：

1. 联系人身份：头像、显示名、微信号、发消息。
2. 客户画像：等级、来源、画像标识、最近备注，右侧编辑图标。
3. 联系人标签：当前真实联系人标签，右侧编辑图标。
4. 朋友圈权限：仅聊天、不看对方朋友圈、不让对方看我，右侧编辑图标。
5. 共同群聊。
6. 关系动态。

画像映射标签和微信联系人标签必须使用不同文案：

- 画像中的 `mappedLabelNames` 显示为“画像映射标签”。
- 联系人详情 `labels` 显示为“联系人标签”。

两者不互相自动复制。

## 3. 编辑交互

### 3.1 通用模式

编辑不再使用长表单 `AlertDialog`，而是在联系人面板内进入独立子页。每个子页都有：

- 顶部返回、标题和联系人名称。
- 可滚动编辑区。
- 底部稳定操作栏：取消、预览修改。
- 预览修改后进入同一子页的确认态，逐项显示“原值 -> 新值”。
- 确认态主按钮为“确认保存”，保存中禁止重复点击和返回。
- 失败后保留草稿，并提供“重新提交”或“返回修改”。

只有存在实际变更时才能进入确认态。

### 3.2 客户画像

字段分两组：

- 基础画像：客户等级、来源渠道、来源详情、画像标识。
- 运营记录：社交账号、购买记录、备注、画像映射标签。

保存流程：

```text
校验 contactId 与账号路由
  -> PUT /contacts/{contactId}/customer-profile
  -> GET /contacts/{contactId}/customer-profile
  -> 比较用户可编辑字段
  -> 一致：显示“已保存并回读确认”
  -> 不一致：显示差异字段，以回读结果更新页面
```

比较时忽略 `id`、`createdAt`、`updatedAt` 等服务端字段。空文本统一转换为 `null`，标签去空白、去重并保持稳定顺序。

### 3.3 联系人标签

编辑页先读取 `GET /contact-labels?weChatId=...&includeDeleted=false`，再用 `GET /contacts/{contactId}/detail` 确定当前已选标签。

交互使用搜索框加可勾选标签列表，不使用逗号文本输入。顶部固定显示：

- 当前联系人。
- 当前账号。
- 已选数量。
- “本次保存会替换该联系人的完整标签集合”。

如果从非空标签改为空集合，确认页使用警告色并明确写“保存后将清空此联系人的全部联系人标签”。

保存流程：

```text
POST /contacts/labels
  -> 获取 taskId
  -> ScrmContactTaskRunner 等待任务终态
  -> GET /contacts/{contactId}/detail
  -> 比较标签 ID/名称集合
  -> 一致后更新详情页
```

首版只使用单联系人 `setContactLabels`，不得调用 batch 或 batch-by-filter。

### 3.4 朋友圈权限

权限显示口径：

- `permissionMask=0`：普通好友。
- `permissionMask=1`：不看对方朋友圈。
- `permissionMask=2`：不让对方看我。
- `permissionMask=3`：后两项同时开启。
- `permissionMask=8`：仅聊天。

只有 `friendPermissionSynced=true` 时，详情页才把状态显示为已同步。未同步时显示“状态未同步”，编辑页使用三态控件“未指定 / 开启 / 关闭”，三项都明确选择后才允许保存。

编辑项：

1. 仅聊天。
2. 不看对方朋友圈。
3. 不让对方看我的朋友圈。

开启“仅聊天”后，后两项自动切换为关闭并禁用，因为接口文档明确仅聊天会覆盖两个朋友圈权限。关闭“仅聊天”后，后两项保持关闭，由用户重新选择。

保存请求同时提交 `permissionMask` 和三个布尔值，二者必须由同一个纯函数生成，禁止 UI 分别拼装。

保存流程：

```text
POST /friends/permissions
  -> 获取 taskId
  -> 等待任务终态
  -> GET /contacts/{contactId}/detail
  -> 校验 friendPermissionSynced 和 friendPermissionMask
  -> 一致后更新详情页
```

## 4. 状态设计

三类编辑共用以下状态语义，但数据草稿独立：

| 状态 | UI 行为 |
|---|---|
| Loading | 展示字段骨架，禁止编辑 |
| Ready | 展示服务端快照，可进入编辑 |
| Editing | 草稿可修改，返回时有未保存提醒 |
| Reviewing | 展示变更对比，不发送请求 |
| Saving | 禁止重复提交，显示当前步骤 |
| Verifying | 显示“任务成功，正在回读确认” |
| Saved | 返回详情并显示已回读确认状态 |
| SavedWithDifferences | 显示差异字段，以服务端值为准 |
| Failed | 保留草稿，展示原始错误，可重试 |
| Blocked | 路由缺失、权限未同步或后端频控，说明阻塞原因 |

状态消息固定在页面内容顶部或底部操作栏上方，不使用 Toast 承载保存结果。

## 5. 代码边界

### 5.1 UI 层

- `ScrmContactProfilePanel.kt`：只展示详情和发出编辑意图，移除请求组装逻辑。
- 新增 `ScrmCustomerProfileEditor.kt`：画像草稿、字段校验、变更预览。
- 新增 `ScrmContactLabelsEditor.kt`：标签搜索、选择、清空警告、变更预览。
- 新增 `ScrmFriendPermissionsEditor.kt`：权限三态编辑和覆盖规则说明。
- 新增 `ScrmContactEditorState.kt`：纯状态、草稿和差异计算函数。

Composable 不持有 `ScrmApiClient`，不直接调用网络。

### 5.2 Host 层

`ScrmContactsPanel.kt` 继续负责协程、账号路由和页面导航，但写操作拆为小函数：

- `saveSelectedCustomerProfile(draft)`
- `saveSelectedContactLabels(selection)`
- `saveSelectedFriendPermissions(draft)`
- `reloadSelectedContactSnapshot()`

所有 API 调用在 `Dispatchers.IO` 执行。标签和权限复用 `ScrmContactTaskRunner`，画像使用 PUT 后 GET 回读。

### 5.3 接口层

复用已有方法：

- `saveCustomerProfile`
- `setContactLabels`
- `setFriendPermission`
- `getCustomerProfile`
- `getContactDetail`
- `getContactLabels`

不新增 fallback、mock 成功或吞错。服务端错误通过现有 `toScrmContactsPanelMessage()` 转为用户可见文本，同时保留日志中的路由和 taskId，不记录 API Key 或完整敏感内容。

## 6. 视觉与可用性

场景：用户在其他应用上方的窄悬浮窗口中快速维护一个联系人，环境通常明亮且任务连续，因此采用浅色高对比工作界面。

- 使用现有系统字体和 Compose Material 控件。
- 页面底色沿用冷灰，内容区使用白色全宽分区；不新增玻璃卡片和装饰渐变。
- 主操作使用现有绿色强调色；警告和破坏性清空使用受控红色。
- 点击区域至少 48dp，字段标签和状态不能依赖颜色单独表达。
- 窄窗口下保持单列；键盘出现时底部操作栏随所属容器处理 Insets，不能遮挡最后一个字段。
- 状态变化使用 150 至 250ms 的淡入或内容切换，不动画布局尺寸。

## 7. 错误与边界

- 缺少有效 `contactId`、`deviceUuid`、`weChatId` 或 friend wxid 时，编辑入口禁用并显示缺失项。
- 切换账号或联系人时丢弃旧快照，取消正在进行的读取；保存中不允许切换。
- 标签字典加载失败时，不允许用空列表覆盖已有标签。
- 权限未同步时不能把未知值当作关闭；必须逐项明确选择。
- 任务超时、未知终态、后端频控和回读不一致分别显示，不能合并成“保存失败”。
- 回读失败时状态为“写入结果待确认”，不能显示保存成功。
- 写入成功后只有回读结果更新详情，禁止用草稿直接覆盖服务端快照。

## 8. 测试与验收

### 自动化测试

自动化不得访问真实 POST/PUT 接口，只覆盖：

- 画像草稿规范化和字段差异。
- 标签选择集合、清空警告和替换语义。
- 权限 mask 与三项布尔值的双向映射。
- `friendPermissionSynced=false` 的未知状态。
- 状态机从 Editing -> Reviewing -> Saving -> Verifying -> Saved/Failed。
- MockTransport 的方法、路径、请求体和响应解析。
- Host 在任务终态后调用详情回读，失败时保留草稿。

### 人工验收

1. 使用测试联系人记录原画像、标签和权限。
2. 三类功能分别只修改一项，每次只执行一次真实写入。
3. 按 taskId 确认终态，再用 GET 回读。
4. 验证失败、频控、未知权限、清空标签确认和回读不一致状态。
5. 恢复测试联系人的原数据。

消息发送、朋友圈发布、批量标签和批量权限不在本功能验收范围内。

## 9. 完成标准

- 联系人详情能准确展示三类服务端快照和同步状态。
- 三类编辑均经过变更预览和确认，不存在单击即写入。
- 画像保存后回读；标签和权限等待 task 终态后回读。
- 回读前不显示成功，回读差异明确展示。
- 自动化测试不调用真实写接口。
- `完成进度.md`、`任务计划.md`、`功能对照.md` 同步真实状态。
