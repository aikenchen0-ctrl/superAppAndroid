# 悬浮聊天统一工作区布局设计

## 目标

将顶部状态栏与 Toolbar、聊天主体、底部输入栏纳入统一的垂直工作区，消除依赖绝对定位和重复 padding 造成的空隙，为后续增加搜索、会话上下文和工具入口提供稳定插槽。

## 结构

```text
FloatingChatRuntimeSections
└── FloatingChatWorkspace (Box overlay host)
    ├── Column
    │   └── CoordinateChatBody (顶部 Toolbar + 主体)
    │       ├── ChatTopToolbar
    │       └── ChatBodyContent (weight=1)
    │   └── BottomInputBar (键盘/导航栏 Insets 边界)
    ├── FloatingBottomPanel (抽屉或居中面板)
    └── Gesture/Media/Toast Overlays
```

`CoordinateChatBody` 内部改为 `Column`，Toolbar 占用固定顶部高度，消息列表和左右轨道只在主体 slot 中布局，不再使用顶部 72dp 避让。工作区底部 slot 负责输入栏的测量和 Insets，聊天主体不再预留底部高度。

## 交互与数据流

消息点击、空白点击、会话选择、左右轨道、连接线和搜索状态保持原有回调路径。底部 Emoji/More 抽屉继续在 Overlay 层渲染，并通过 `composerHeader` 复用输入栏；普通输入栏仅在非底部抽屉和非居中面板状态显示。

## 边界与约束

- 只修改 Compose UI 布局和布局契约测试。
- 不修改 SCRM API、请求模型、桥接逻辑或消息业务状态。
- `WindowInsets.ime`、`navigationBarsPadding` 只能由底部工作区 slot 处理一次。
- 居中工具面板仍覆盖整个工作区并保留现有 scrim、关闭和动效。

## 验证

- 纯布局策略测试确认工作区使用顶部/主体/底部三个垂直 slot，主体不再计算 Toolbar 或底部栏的重复 reserved padding。
- 运行 `:ubiki-accessibility:testDebugUnitTest` 和 `:app:assembleDebug`。
- 记录全量测试中与本次布局无关的既有失败，不扩大修复范围。
