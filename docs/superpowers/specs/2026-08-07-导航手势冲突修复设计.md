# 导航手势冲突修复设计

## 目标

在不改变现有全屏 `TYPE_ACCESSIBILITY_OVERLAY` 技术选型的前提下，让配置的左右边缘手势在 Android 系统侧边返回手势开启时保持可触发，并为 ROOT 与非 ROOT 设备提供可恢复、可验证的分层策略。

## 根因

- 普通边缘触发条由 `EdgeOverlayView` 承载，已在 API 29+ 申请自身小窗口的手势排除区。
- Android 13+ 的 `NativeEdgeGestureController` 改用 `TouchInteractionController` 在无障碍服务层消费触摸，不再创建小窗口，因此没有可调用 `View.setSystemGestureExclusionRects()` 的 View。
- 展开浮聊在原生触摸不可用时由全屏 Compose 内部手势承载，同样没有小窗口排除区。
- Android 官方 API 只会采纳每条侧边最多 200dp 的纵向排除范围。现有 `NativeBackGestureTakeoverController` 试图直接写安全设置来绕过限制，但普通应用没有权限，且没有 ROOT Shell、按侧决策或恢复路径。

## 方案对比

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 仅保留现有小触发条 | 改动小 | 不覆盖原生触摸和展开浮聊全屏手势 | 不采用 |
| 全屏可触摸 Overlay | 能接收边缘触摸 | 会拦截聊天和底层应用的普通点击 | 不采用 |
| 全屏非触摸排除区 Overlay + ROOT 按侧增强 | 覆盖全部触摸路径，不阻塞 UI，非 ROOT 有官方回退 | ROOT 增强只能改变系统级设置，必须严格恢复 | 采用 |

## 架构

```text
每层 EdgeZoneConfig
        |
        +--> nativeTouchInterceptRects() --------------> NativeEdgeGestureController
        |                                                       |
        |                                                       +--> 服务层触摸消费
        |
        +--> 全屏非触摸 GestureExclusionOverlayView ---> setSystemGestureExclusionRects()
        |                                                       |
        |                                                       +--> API 29+ 官方排除区
        |
        +--> 垂直并集超过 200dp 的左右侧 -------------> Root Back Takeover
                                                                |
                              API 29+ 仅写对应侧 back_gesture_inset_scale=0
                              API 26-28 仅通过 `wm overscan` 隐藏旧式底部导航栏
                                                                |
                                                        服务停用/屏幕关闭/配置缩短时恢复
```

## 组件

### 全屏排除区 Overlay

新增 `NativeGestureExclusionOverlayController`，创建 `MATCH_PARENT` 的 `TYPE_ACCESSIBILITY_OVERLAY`。窗口使用 `FLAG_NOT_TOUCHABLE`、`FLAG_NOT_FOCUSABLE`、`FLAG_NOT_TOUCH_MODAL`、`FLAG_LAYOUT_IN_SCREEN`、`FLAG_LAYOUT_NO_LIMITS` 和 `FLAG_LAYOUT_IN_OVERSCAN`，因此覆盖状态栏和导航栏但不接管任何触摸。

它只在以下情况存在：

- Android 13+ 原生 `TouchInteractionController` 路径正在工作；
- 展开浮聊拥有全屏内部边缘手势而普通小触发条不允许存在。

它永远只提交每个实际 `NativeTouchInterceptRect`，绝不提交全屏矩形、底部栏矩形或视觉效果窗口矩形。视图附加、尺寸变化、配置更新和移除时都会重算或清空排除区。

### ROOT 接管

重构现有 `NativeBackGestureTakeoverController`：

- 使用 `su -c` 执行静态、无用户输入拼接的 `settings` / `wm` 命令；不再直接调用 `Settings.Secure.putString()`。
- API 29+：仅对排除需求的垂直并集超过 `200dp` 且触发区贴紧物理边缘的一侧，保存原 `back_gesture_inset_scale_left/right` 后设置为 `0`。
- API 26-28：仅在有活动边缘手势且检测到可用导航栏高度时，尝试 `wm overscan 0,0,0,-<height>`；失败不会影响 Overlay 路径。
- 每次服务暂停、关闭、屏幕熄灭、配置改为不需要增强或服务销毁时，恢复本组件自己保存的设置。原本不存在的安全设置通过 `settings delete secure` 恢复。
- ROOT 探测、命令失败和恢复失败写入 `Log`，不伪造成功；非 ROOT 设备继续走官方排除区。

## 生命周期

- `onServiceConnected()` 初始化排除区 Controller 和 ROOT Controller。
- `createOverlays()` 根据当前输入模式和浮聊状态同步小触发条、全屏排除区和 ROOT 策略。
- `handleFloatingChatExpandedChanged()` 在普通触发条和全屏浮聊手势之间切换时同步排除区。
- `removeAllOverlays()`、屏幕关闭和 `onDestroy()` 先清空 View 排除区，再恢复 ROOT 改动。

## 非目标

- 不将 `TYPE_ACCESSIBILITY_OVERLAY` 替换为 `TYPE_APPLICATION_OVERLAY`。
- 不全局切换 `navigation_mode`，不关闭底部 Home/最近任务手势。
- 不为视频、波纹和其他非边缘触摸 Overlay 声明排除区。
- 不对 Android 10+ 使用 `wm overscan` 作为侧边返回冲突的替代方案。

## 验收

- API 33+ 原生触摸模式和展开浮聊回退模式都生成与实际 `EdgeZoneConfig` 一致的局部排除矩形。
- 配置“侧边留空”后，矩形从相应 inset 开始，不误占物理边缘空白。
- 非 ROOT 下不崩溃、不改系统设置，官方 200dp 以内的配置正常申请排除区。
- ROOT 下只有超过 200dp 的贴边侧禁用系统 Back 手势；退出时恢复原设置。
- API 26-28 的 ROOT `wm overscan` 失败不会影响正常 Overlay；停止服务时会尝试恢复。
