# 消息类型展示设计

## 目标

将悬浮聊天消息按内容语义渲染为轻量气泡、业务卡片、独立媒体或状态占位。界面参考微信的快速识别方式，避免把可点击资源、媒体和不可查看消息伪装成普通文本。

## 范围与约束

- 只调整 Android Compose 展示层和本地展示模型，不修改 SCRM 接口、远端消息协议或发送逻辑。
- 保持现有消息交互：点击、长按、多选、媒体预览和业务卡片入口。
- 不可查看内容必须显示原因与可执行状态，不能渲染为空白或伪造正文。

## 样式分组

| 展示组 | 消息类型 | 视觉规则 |
| --- | --- | --- |
| 轻量气泡 | Text、MixedText、Quote | 微信式左右对齐气泡；引用消息内嵌弱化引用块；AI 草稿保留虚线提示。 |
| 独立媒体 | ImageThumbnail、VideoPreview | 不套普通气泡背景；保留原比例缩略图。视频显示播放图标、时长和媒体不可用状态。 |
| 业务卡片 | Location、ContactLink、MiniProgramLink、FilePreview、ChatHistory、InlineContact、InlineLocation、Voice | 使用浅底、细边框、内容分区。位置带地图预览，名片带头像和身份信息，小程序带应用标识，文件带格式和大小，聊天记录带摘要，语音保持固定宽度与时长。 |
| 支付卡片 | 转账、红包等 MiniProgramLink 支付子类型 | 沿用高识别度橙色业务卡片和领取状态。 |
| 系统提示 | presentation=System | 居中弱化文本，不套消息气泡。 |
| 状态占位 | 已撤回、受权限限制、内容不支持、媒体已失效、空载荷或解析失败 | 居中或随发送方对齐的紧凑状态卡，图标、原因和辅助文案明确；不可预览时禁止进入媒体预览。 |

## 不可见消息状态

新增本地展示状态枚举，不改变远端字段。状态由现有消息字段推导：

- `text`、`detail`、资源字段均为空：内容暂不可查看。
- `accessState=NeedsApply`、`Applied`：需要申请或正在等待授权。
- 媒体消息缺少可用缩略图与本地/远端资源：媒体已失效。
- 未识别的内容类型或技术值：暂不支持的消息。
- 服务端明确的撤回标识接入后映射为已撤回消息。

展示策略和状态推导必须是纯函数，便于 SCRM 映射层以后补充字段而不影响 UI 渲染入口。

## 架构

在 `floatingchat/message` 中建立消息展示策略：它根据 `FloatingChatMessage` 返回样式组与不可见状态。`MessageContent` 只按策略分派到已有内容组件或新的状态卡组件。颜色和圆角继续由 `OverlayTokens` 与 `MessageBubbleStyle` 管理，避免在各内容组件散落重复判断。

## 测试

- 为每个消息类型验证其展示组。
- 为缺正文、授权中、媒体失效、未知内容验证对应的状态占位。
- 验证媒体失效状态不会触发预览；系统消息仍无普通气泡；支付卡片仍沿用现有卡片。
- 运行 `FloatingChatMessageUiContractTest` 中的新用例，并构建 Debug APK。当前并行 SCRM 修改造成的无关编译错误需单独记录，不在本设计内修复。
