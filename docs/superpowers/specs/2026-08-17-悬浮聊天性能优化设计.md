# 悬浮聊天性能优化设计

## 目标

在不修改消息渲染、接口逻辑、UI 样式、现有功能和业务语义的前提下，降低悬浮聊天滚动、未读总览和连接线绘制期间的主线程计算与临时对象分配。优化以固定真机手势的帧时间改善和行为回归通过为验收依据，不通过节流、降质、丢更新或静默降级换取性能。

## 当前状态与阻力

- OnePlus 9 固定滚动基线的暖态卡顿率为 `24.38%` 至 `29.42%`，P95 为 `36ms` 至 `38ms`。
- 慢帧以慢 UI 线程和慢绘制命令为主，三轮慢位图上传均为 0。
- 坐标状态已具备精确 `Rect` 等值短路；Canvas 读取版本只重启绘制，旧报告中的整树重组结论已经过期。
- 未读摘要仍按线程重复扫描全量消息，分组追加仍反复复制列表，总览分支还构建不会消费的普通线程结果和离屏索引。
- 连接线每帧仍创建单项列表、目标键及 Tree/Brace/Pair/List 等几何对象图。
- 控制器仍存在构造期同步数据库读取和少数强制重建，但异步首屏会改变可见数据时序，当前禁区下不贸然调整。

## 约束

- 用户约束：必须自主实现、自动验证并提供量化结果。
- 禁区约束：不改消息内容或布局，不改请求、响应、刷新、重试和缓存语义，不改颜色、尺寸、动画、阴影或连接线路径，不改点击、滚动、输入、语音等功能。
- 基底约束：Compose 状态、消息顺序、分组首次出现顺序、连接器 ID、未读回退规则和错误暴露方式必须保持一致。
- 代偿约束：不能用 debounce、采样、坐标阈值、延迟补线、关闭绘制或缓存陈旧结果降低负载。

## 候选方案

### 方案 A：纯计算与逐帧分配最小化

1. 未读摘要一次扫描建立精确线程索引，保留显式线程和 User/Account/None 回退的原顺序语义。
2. 未读分组使用可变桶线性追加，最终一次冻结；调用方只派生一次分组结果。
3. 总览模式不计算随后丢弃的普通线程消息，也不构建总览连接线不会读取的离屏索引。
4. 连接线预计算消息目标键，普通列表项直接处理单条消息，删除恒等映射和历史空 key。
5. 若第一轮收益不足，将运行时 Tree/Brace 对象图替换为直接写入复用 `Path` 的等价 writer，保留现有纯几何函数与测试。

成本低、滚动热路径收益直接，且可用精确输出测试证明无业务和视觉变化。本轮采用。

### 方案 B：调整窗口和 Compose 生命周期

在全屏覆盖或折叠时暂停聊天子树，或异步化控制器初始数据库快照。潜在收益覆盖首开与后台场景，但会改变 remembered 状态、任务生命周期或首屏数据时序，与禁区冲突风险高，本轮不采用。

### 方案 C：降低视觉或坐标精度

关闭阴影/模糊/连接线、减少坐标更新、滚动停止后再补绘。性能收益可能明显，但直接改变 UI 样式或实时行为，明确拒绝。

## 数据路径设计

### 未读摘要索引

每个账号会话只扫描消息一次，同时记录：

- 非空 `threadContactId` 对应的消息列表；
- 无线程 ID 时按 User 联系人、Account 账号和 None 分类的消息及原始索引；
- 候选线程的首次出现顺序。

查询某个候选线程时优先返回显式线程消息；缺失时按现有 `visibleMessagesForThread()` 规则合并回退桶，并保持源消息顺序。未读判断、最后一条摘要、计数、头像和复制字段完全沿用现有函数。

### 未读总览派生

`homeOverviewMessageGroups()` 使用 `LinkedHashMap<GroupKey, MutableList<Message>>` 保留组首次出现顺序，组内直接追加保留消息顺序。最终组的 `connectorId` 仍由首条消息生成。`CoordinateChatBody` 仅计算一次分组结果，并从该结果构建 message-to-connector 映射。

总览模式使用空离屏索引，因为绘制层在该模式下不会读取离屏边缘；普通模式保持原索引算法。总览模式直接选择摘要消息，普通模式才扫描当前线程。

### 连接线绘制

稳定输入变化时预先构建 `message.id -> ConnectorTargetKey?`，draw 阶段只读取。普通模式直接读取可见 item 对应消息，不创建临时单项列表。scratch 容器的生命周期键覆盖账号、群成员头像开关和总览连接器映射，避免状态切换后保留空键。

直接 Path writer 若启用，必须逐命令复现现有 trunk、hook 排序、半径、重叠和 `moveTo/quadTo/lineTo` 顺序；不改变 Paint、路径绘制顺序或像素参数。

## 验证标准

- 确定性复杂度：大量显式线程下，未读摘要源消息元素读取不超过 `2M`；总览分组不出现逐条不可变列表相加。
- 输出等价：现有及新增分组、fallback、摘要、连接线几何测试全部通过。
- 静态契约：`CoordinateChatBody` 只调用一次分组函数，总览不会构建普通离屏索引。
- 工程验证：定向单测、模块单测、Kotlin 编译、Debug APK 构建和 `git diff --check` 通过；测试设置 60 秒上限。
- 真机验证：使用同一设备、同一聊天、同一 12 次往返滚动采集三轮 `gfxinfo`，同时复核输入、会话切换、总览、语音点击、截图和日志异常。
- 帧指标以暖态两轮中位趋势为主；若无稳定改善，继续定位并实施下一项等价热路径优化，不用单轮最佳值宣称成功。

## 已确认的 toolbar 局部扩展

最新用户请求明确覆盖 toolbar 的局部视觉约束。实际显示的全屏悬浮聊天 header 保持共享 `surface`、30dp 状态区 Insets 和原有 callback 链，仅将内容组织为两个等权区域：左侧返回按钮、右上未回红点、五字符宽度的会话名走马灯、编辑按钮；右侧为二维码入口、三字符宽度的账号名走马灯和搜索按钮。二维码、搜索、添加好友/群聊继续进入既有工作区。

私聊编辑继续打开现有联系人资料页，并同时显示一个挂在同一 Compose 悬浮根内的备注输入层。确认操作复用现有本地资料持久化入口，不引入网络调用、Android Dialog Window、静默错误或自动重试。群聊编辑继续进入既有群信息工作区，保持群备注接口和页面不变。
