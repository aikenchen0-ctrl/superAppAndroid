# 未回消息双向连接线设计

## 目标

在 Android 未回消息聚合页中补充双向归属连接线，让用户同时看清：

- 左侧联系人头像对应哪些连续未回消息。
- 每条未回消息由右侧哪个账号接收。

底部 Home 键、底部输入栏、未回消息入口和聚合页状态恢复行为保持不变。

## 展示规则

### 联系人头像到消息气泡

- 同一个未回事项只显示一个左侧联系人头像。
- 从联系人头像引出一条主干，再分支连接该事项当前可见的全部消息气泡。
- 同一事项包含多条连续未回消息时不重复绘制头像到气泡的独立长线。
- 主干和分支使用现有连接线的圆角折线路径、颜色、阴影和层级。

### 消息气泡到账号栏

- 每条未回消息从气泡右侧连接到所属收件账号头像。
- 同一账号的多条可见消息复用现有树形收束能力，避免在账号栏附近形成完全重叠的独立线段。
- 账号筛选不会改变消息与账号的归属关系；单账号视图仍连接到该账号头像。

## 坐标与数据流

- `HomeOverviewAvatarRail` 继续登记聚合事项左侧头像边界。
- `MessageCoordinatePane` 为聚合消息登记气泡边界，不创建第二套坐标状态。
- `RightCoordinateRail` 继续登记右侧账号头像边界。
- `ChatConnectorLayer` 在聚合页中同时读取事项连接 ID、消息气泡边界和账号 ID，生成左右两类连接树。
- 连接关系使用稳定的事项 ID、消息 ID 和账号 ID，不依赖列表位置。

## 滚动与生命周期

- 只为当前可见列表项绘制完整分支。
- 离屏消息使用现有预计算目标维持主干方向，不读取不存在的 Compose 节点坐标。
- 切换筛选、进入会话、消息更新或事项消失时，清理不再有效的头像和气泡坐标。
- 列表滚动不得改变事项分组或把连接线错误指向相邻事项。

## 交互与配置

- 连接线不拦截点击、长按、滚动或草稿输入。
- 不新增连接线开关或配置菜单项。
- 不修改 `BottomInputBar.kt`，不修改底部 Home 键行为。
- 保留头像水印和账号色点现有配置。

## 错误处理

- 某个端点坐标尚未就绪时不绘制对应分支，不使用猜测坐标或假端点。
- 坐标可用后由 Compose 重绘恢复连接线。
- 缺少账号或联系人数据时保留消息展示，并跳过无法建立真实归属的连接线。

## 测试策略

- 单元测试验证聚合页启用连接层。
- 几何测试验证同一事项左侧形成单主干多分支。
- 几何测试验证每条聚合消息连接到其所属账号。
- 契约测试验证聚合消息、事项连接 ID 和账号 ID 的映射稳定。
- 回归测试验证普通会话连接线行为不变。
- 构建 Debug APK，并在 ADB 设备上覆盖安装后人工检查滚动、筛选和多账号场景。

## 验收标准

1. 全账号和单账号未回消息聚合页均显示双向连接线。
2. 左侧一个联系人头像通过树形主干连接同一事项的全部可见气泡。
3. 每条气泡连接到正确的右侧收件账号头像。
4. 多条连续消息滚动时无跨事项串线、明显残留线或触控阻挡。
5. 普通聊天连接线、底部 Home 键和底部输入栏行为不变。
