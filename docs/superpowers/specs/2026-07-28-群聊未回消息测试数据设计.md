# 群聊未回消息测试数据设计

## 目标

在 Debug 版本中复用手机当前账号的真实群聊，注入覆盖群聊未回判定边界的演示消息；Release 版本不注入。测试人员无需创建额外虚拟群，可直接在全账号未回消息聚合页检查结果。

## 数据边界

- 仅为现有群聊生成数据，不新增群、不修改联系人和账号。
- 正例必须满足当前未回规则：来自对方、文本类型、普通气泡、连接到群成员、正文非空，且位于最后一次我方回复之后。
- 负例覆盖空白文本、我方消息、AI 草稿、系统消息、特殊卡片及所有非文本消息类型，确保它们不会形成未回事项。
- 当群成员资料可用时，多成员场景轮换真实成员；资料不足时使用群联系人作为可解析目标，不伪造远端业务数据。

## 场景矩阵

每个现有群按稳定序号分配一组场景，消息 ID 和正文带场景标识，覆盖：

1. 单条未回文本。
2. 同成员连续多条。
3. 多成员交替发言。
4. 我方回复后出现新消息，仅新消息计入未回。
5. 我方最后回复，无未回事项。
6. `@我`、`@所有人`、普通文本。
7. 长文本、Emoji、中英文、特殊符号、空白文本。
8. 相同显示时间与稳定唯一 ID。
9. 图片、视频、语音、文件、位置、名片、小程序、引用、聊天记录、混合文本等排除类型。
10. 系统通知、撤回提示、AI 草稿等排除状态。
11. 多账号、多群和足量消息，用于聚合滚动、账号筛选和返回位置检查。

若手机仅有一个群，所有场景按顺序放入该群；若存在多个群，则稳定轮转分配，仍保证全部场景出现。

## 结构

新增 `ScrmGroupUnrepliedDebugFixtures.kt`，负责纯函数式生成群聊演示消息。`ScrmFloatingChatBridge.kt` 只负责在 Debug 构建调用生成器，并与原有私聊演示数据合并。生成器不访问网络、不持久化、不修改输入对象。

## 验证

- 单元测试验证 Debug 数据覆盖正例、回复边界、消息类型负例、唯一 ID、多成员和所有现有群。
- 单元测试不再依赖固定总数 `30`，改为按场景契约断言。
- 运行模块单测、Debug 编译和 APK 构建。
- 通过 ADB 安装到设备 `d0512adb`，启动并检查未回消息聚合页。
