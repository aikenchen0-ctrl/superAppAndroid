# 全局返回手势扇形双框设计

## 目标

在现有全局返回手势的箭头拉出反馈旁增加两个可选功能框，交互参考微信语音输入的拖动选择体验。本期只增加固定占位的视觉和命中区域，不实现、不记录任何真实功能动作。

## 已确认行为

- 两个固定占位框文案为“功能一”和“功能二”。
- 采用扇形布局，两个框围绕返回箭头向屏幕内侧上下分叉。
- 左右边缘均支持，右边缘对布局和命中区域做水平镜像。
- 手指刚开始向内移动时显示双框，并随拖动连续展开。
- 触点进入哪个框就显示哪个框的高亮；命中不依赖固定的上下或左右语义映射。
- 松手命中任一功能框：只收回视觉层，不记录、不调用动作执行器、不执行返回。
- 松手未命中功能框：继续执行原有已配置返回手势动作。
- `ACTION_CANCEL`、无效内收方向或 Overlay 清理：只清理临时选择状态，不触发新动作。
- 不新增设置项、不新增偏好键、不接入 `GestureActionCatalog`，不修改 `UbikiPreferences`、`UbikiActionExecutor` 和设置页。

## 架构与数据流

保持当前触摸分发和无障碍架构不变：

```text
MotionEvent
  -> EdgeGestureDetector / NativeEdgeGestureController
  -> BackGestureProgress
  -> BackGestureOptionHitTester（纯 Kotlin 几何判定）
  -> BackGestureSelection(None / FunctionOne / FunctionTwo)
  -> BackWaveOverlayController 绘制箭头、双框和高亮
```

### 输入层

- 在 `ubiki-overlay` 的 `EdgeGestureDetector` 和 `ubiki-accessibility` 的 `NativeEdgeGestureController` 中复用同一套纯几何判定逻辑。
- 命中判定必须由触摸坐标、起点、边缘方向、density 和当前布局参数计算，不得从 Canvas 像素、View 点击或无障碍节点反推。
- 推荐在 `ubiki-core` 增加小型 `BackGestureOptionHitTester`（名称可按现有命名约定调整），并返回 `BackGestureSelection` 状态。
- 选择状态应沿现有进度回调传递到 `BackWaveOverlayController`，避免两个输入路径产生不同规则。

### Overlay 层

- 继续使用 `BackWaveOverlayController` 的 `TYPE_ACCESSIBILITY_OVERLAY`。
- 保持 `FLAG_NOT_TOUCHABLE`，不新增可触摸 Overlay，不抢占系统返回、悬浮聊天或底部手势条触摸。
- Canvas 的绘制布局和命中器必须共享同一份几何计算，确保视觉框与实际命中区域一致。
- Overlay 添加、更新、移除异常沿用现有日志和清理路径，不吞掉错误，也不伪造动作成功。

### 提交层

- `ACTION_UP` 时先读取最终选择状态。
- 选择为 `FunctionOne` 或 `FunctionTwo`：关闭返回波纹，消费此次手势，跳过 `onBackGestureCommit` 和后续 `onGesture`/`executeConfiguredGestureAction`。
- 选择为 `None`：保持现有 `onBackGestureCommit`、短拉/长拉分类和动作执行顺序。
- `ACTION_CANCEL` 或进度失效：关闭返回波纹并清除选择状态。

## 扇形视觉与几何

- 上方框显示“功能一”，下方框显示“功能二”。
- 两个框相对当前箭头和 `startY` 定位，不使用屏幕绝对坐标。
- 建议默认尺寸约为 `72dp x 44dp`，圆角约 `12dp`，框间距至少 `12dp`；实际参数应集中为命名常量并根据 Overlay 可用宽度调整。
- 选项框随拖动进度从箭头附近向内侧连续 alpha/scale 展开；不增加第二个离散阈值。
- 未选中状态使用低透明度描边/填充，命中状态提高对比度并轻微放大；返回箭头原有波纹、方向提示和长距离形变保持。
- 左右边缘几何布局水平镜像；在顶部、底部、横屏和不同 density 下都必须限制在 Overlay 可见范围内。
- 功能框不得覆盖系统状态栏、底部导航区域或现有边缘触摸区之外的无关交互区域。

## 兼容性约束

不得改变以下行为或模块：

- `GestureAction`、`GestureActionCatalog`、`UbikiPreferences`、设置 UI、`UbikiActionExecutor`。
- `EdgeOverlayView` 的触摸区和系统手势排除区域。
- 原生 `TouchInteractionController` 的委托/回退策略。
- 底部手势条、悬浮聊天内部返回、媒体预览关闭和媒体操作菜单关闭。
- 现有左右边缘短拉、长拉、斜向滑动和未命中时的默认动作。

## 测试与验收

### 单元测试

1. `BackGestureOptionHitTester`：左/右镜像、上/下框命中、框外不命中、边界点、箭头附近不误命中、不同 density 和退化尺寸。
2. Overlay 视觉计算：第一像素开始渐入、双框不重叠、左右镜像、顶部/底部不越界、选择高亮与命中几何一致。
3. 手势链路：命中框不调用 `onBackGestureCommit` 且不触发动作；未命中保持原动作；`ACTION_CANCEL` 清理状态；短拉/长拉默认行为不变。

### 回归验证

- 运行现有 `ubiki-core`、`ubiki-overlay`、`ubiki-accessibility` 测试。
- 在真机或模拟器验证左边缘、右边缘、快速/慢速拖动、斜向拖动、横竖屏、顶部/底部触点和悬浮聊天展开状态。
- 验收必须确认：无新增设置项、无真实功能调用、命中框不返回、未命中框与改动前行为一致、Overlay 不抢触摸、不残留。

## 非目标

- 不实现“功能一/功能二”的具体业务。
- 不把两个占位框映射到系统动作、应用启动、浮窗操作或任意 `GestureAction`。
- 不增加偏好存储、设置页入口、网络请求、埋点或持久化选择记录。
- 不重写现有返回动画，不迁移 Overlay 技术栈，不改动无关悬浮聊天代码。
