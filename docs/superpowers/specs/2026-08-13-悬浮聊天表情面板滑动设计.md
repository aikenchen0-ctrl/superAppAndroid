# 悬浮聊天表情面板滑动设计

## 目标

底部第一个笑脸按钮继续打开现有表情面板。表情数量超过面板可见高度时，用户可以在表情区域内纵向滑动浏览全部内容，分类栏和底部输入栏保持固定。

## 范围

- 只修改现有 `EmojiPanel` 的表情网格布局和滚动状态。
- 保留当前 300dp 面板高度、8 列布局、4 个分类、表情尺寸和点击插入行为。
- 不修改表情数据来源、分类内容、发送逻辑、SCRM 接口或底部其他工具面板。

## 方案

表情区域使用 Compose `LazyVerticalGrid`，列数固定为 8。网格通过 `Modifier.weight(1f)` 占用分类栏下方的剩余高度，因此只有表情网格响应纵向滚动，分类栏不会随内容移动。

每个分类使用独立的 `LazyGridState`。用户切换分类再返回时，恢复该分类之前的滚动位置，避免大量表情浏览过程中重复定位。表情项使用稳定的“分类索引 + 表情索引”键，避免重复字符造成懒加载状态混淆。

选择表情后沿用现有 `onInsertText` 回调，面板保持展开，滚动位置不重置。

## 性能约束

- 不再通过 `chunked(8)` 一次性组合当前分类的全部行。
- 只组合和绘制可见网格项及少量预取项。
- 不增加自定义滚动容器、嵌套垂直滚动或手势转发层。
- 分类切换只替换网格数据和对应滚动状态，不重建面板外层。

## 交互边界

- 在网格内向上拖动时，内容向上移动并显示后续表情；向下拖动可以返回前面的表情。
- 到达首尾边界时保持 Compose 标准边界行为，不关闭面板，不触发底部按钮，也不移动输入栏。
- 点击分类切换数据；点击表情插入输入框；两种操作均不关闭面板。
- 保持现有触摸尺寸和 Compose 可访问性语义。

## 验收标准

1. 进入任一表情分类后可以纵向滑动到最后一行。
2. 滑动过程中分类栏与底部输入栏位置不变。
3. 切换分类后各分类分别保留自己的滚动位置。
4. 点击表情仍插入输入框，并保持表情面板展开。
5. 源码契约测试确认使用 `LazyVerticalGrid`、8 个固定列、剩余高度约束和独立 `LazyGridState`。
6. `:app:assembleDebug` 通过，并在测试设备上安装验证滑动手势。
