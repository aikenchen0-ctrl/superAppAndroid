# 群聊未回消息展示优先级设计

## 目标

群聊存在多条未回消息时，优先展示与当前账号直接相关或明确要求处理的消息，降低普通群消息造成的信息噪声。私聊未回消息展示规则保持不变。

## 规则

群聊最后一次我方回复之后的有效未回文本，先按现有规则完成未回判定，再执行展示选择：

1. 正文包含 `@当前账号名`。
2. 正文包含当前账号名，即使没有 `@`。
3. 正文包含“待确认”或“回复”。

三类条件按“任一匹配”处理。只要存在优先消息，展示全部匹配消息，并保持原始时间顺序，不混入普通消息。若没有任何优先消息，只展示最新 3 条，并保持从旧到新的顺序。

`unreadCount` 仍表示该群全部有效未回消息数量；`unrepliedMessages` 表示实际展示的消息。私聊继续展示全部有效未回消息。

## 匹配细节

- 当前账号名取 `FloatingChatConversation.accountName`，去除首尾空白后使用。
- 中文按原文包含匹配；拉丁字符使用忽略大小写匹配。
- 账号名为空时，不执行账号名与 `@账号名` 匹配。
- “待确认”和“回复”按正文子串匹配。

## 测试数据

Debug 群聊 fixture 增加明确的“待确认”和“请回复”消息，同时保留普通消息，便于手机确认优先筛选结果。Release 不注入测试数据。

## 验证

- 单元测试覆盖全部优先条件、优先消息全量展示、无优先消息最新 3 条、私聊不截断、未回总数不变。
- 运行模块单测和 Debug APK 构建。
- 通过 ADB 覆盖安装到设备 `d0512adb`。
