# 悬浮聊天消息撤销功能设计

## 目标

在悬浮聊天界面中，为本人发送消息补充真实撤销能力。用户点击消息气泡后，可从包含“话外音、复制、转发、收藏”等操作的现有弹层选择“撤销”，经二次确认后提交 SCRM 撤回接口；只有服务端任务完成后才刷新会话并展示服务端最终状态。

## 交互流程

1. 用户点击本人发送且已同步的消息气泡。
2. 消息操作弹层显示带图标和“撤销”文字的操作按钮。
3. 用户点击“撤销”，操作弹层关闭并显示“确定撤销”对话框。
4. 用户点击“取消”时关闭对话框，不产生写请求。
5. 用户点击“确定”时关闭对话框并提交撤回任务。
6. 任务成功后刷新该消息所属账号的当前会话，由服务端撤回状态更新界面。
7. 请求或任务失败时保留原消息，并通过明确提示显示失败原因。

## 展示条件

“撤销”按钮对 `message.fromMe == true` 的本人消息显示，收到的消息不显示。确认时优先使用消息自身的有效 `remoteMessageId`；本地消息则按 `clientRequestId` 查找已同步副本的远端 ID。仍未同步时不提交写请求，明确提示并刷新会话，避免入口因短暂同步延迟而消失，也避免使用本地 ID 伪调用接口。

## 组件与状态

### 消息操作弹层

在 `MessageLongPressAction` 中新增 `Revoke` 动作，显示文案“撤销”并使用与撤回语义一致的 Material 图标。`messageLongPressActionsFor` 根据消息方向和远端消息 ID 决定是否加入该动作。

### 二次确认对话框

`MessageInteractionOverlayHost` 接收待确认撤销的消息状态，并在现有悬浮 Compose 根内渲染 Google Material 3 风格的模态悬浮卡片。卡片使用 M3 scrim、28dp 圆角、`surfaceContainerHigh` 和 6dp 层级阴影。该确认层不创建 Android `Dialog`、Compose `Dialog`、`AlertDialog` 或第二个 Window，以避免无障碍悬浮窗口出现 `BadTokenException`：

- 标题：`确定撤销`；
- 正文：`撤销后，此消息将从当前会话中撤回。`；
- 确认按钮：`确定`；
- 取消按钮：`取消`。

点击操作弹层中的“撤销”只设置待确认状态，不调用接口。确认回调才进入写操作，确保取消路径没有副作用。

### 操作分发

`MessageLongPressActions` 增加 `onRevokeMessageRequested` 回调。执行 `Revoke` 时关闭操作弹层并将目标消息交给宿主，不直接访问网络，保持 UI 动作与 SCRM 调用解耦。

## 接口与数据流

确认撤销后按以下顺序执行：

1. 再次校验消息来自本人且 `remoteMessageId > 0`；
2. 优先从消息的作用域线程 ID 解析所属账号，旧消息无法解析时才回退当前选中账号；
3. 读取该账号的 `ScrmFloatingAccountRoute`；
4. 构造 `ScrmMessageOperationRequest(deviceUuid, weChatId)`；
5. 调用 `messageOperationApi.revokeMessage(remoteMessageId, request)`；
6. 使用现有 SCRM 任务查询能力等待该任务达到完成、失败或仍在处理状态；
7. 仅在明确完成时调用 `onRefreshConversation(accountId)`。

实际接口为：

```text
POST /openapi/v1/messages/{messageId}/revoke
```

路径中的 `messageId` 必须使用 `FloatingChatMessage.remoteMessageId`，不得使用本地字符串 `id` 或 `remoteMessageServerId`。

## 并发与错误处理

- 同一远端消息正在撤销时阻止重复提交，并提示“该消息正在撤销”。
- 缺少远端消息 ID 时不发送请求，明确提示消息尚未同步。
- 缺少账号路由时不发送请求，明确提示所属账号没有可用的 SCRM 设备路由。
- 提交失败、任务失败和异常均保留原气泡，错误不得被吞掉。
- 任务仍在处理时不伪装成功，也不提前删除消息；提示当前处理状态。
- 协程取消继续向上抛出，不转换为普通失败。

## 明确不做

- 不在接口完成前本地删除或隐藏消息；
- 不支持撤销收到的消息；
- 不为缺少远端 ID 的本地消息增加静默降级；
- 不修改现有“删除”动作的本地隐藏语义；
- 不调整其他消息操作的顺序或行为。

## 测试策略

采用测试驱动方式覆盖：

1. 本人发送且具有有效 `remoteMessageId` 的消息显示 `Revoke`；
2. 收到的消息、本地未同步消息不显示 `Revoke`；
3. `Revoke` 动作关闭菜单并请求打开确认对话框，不直接调用接口；
4. 取消确认不会提交请求；
5. 确认时使用消息所属账号和远端消息 ID 构造撤回请求；
6. 服务端任务完成后刷新正确账号的会话；
7. 提交失败或任务失败时不刷新会话，并保留原消息；
8. SCRM API 客户端仍请求 `/openapi/v1/messages/{messageId}/revoke`。

## 验收标准

- 操作路径完整符合“点击本人消息气泡 → 撤销 → 确定撤销 → 确定”；
- 只有可执行真实撤回的消息显示按钮；
- 确认后真实调用撤回接口并等待任务结果；
- 成功后由服务端刷新结果更新 UI，失败时不产生假成功状态；
- 新增与相关既有测试全部通过。
