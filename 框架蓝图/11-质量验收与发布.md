# 质量验收与发布

## 完成定义

功能完成必须同时满足：代码审查通过、自动化测试通过、真实设备验证通过、用户可理解失败状态、相关文档与验收台账已更新。

## 验收矩阵

| 维度 | 必测项 |
|---|---|
| 权限 | 首次授权、拒绝、撤销、重新授权、服务被系统关闭。 |
| 悬浮窗 | 打开、关闭、旋转、后台前台、锁屏、横屏、键盘。 |
| 手势 | 左右/底部、暂停、黑名单、系统导航冲突、误触率。 |
| 同步 | 空数据、分页、重复、网络超时、服务端 4xx/5xx、恢复。 |
| 聊天 | 文本、媒体、文件、位置、名片、系统消息、多选、草稿。 |
| AI | 超时、拒绝、内容为空、取消、重试、人工确认与审计。 |
| 性能 | 冷启动、首次挂载、滚动、长时运行、内存、耗电。 |
| 安全 | 日志脱敏、凭据扫描、权限最小化、数据删除。 |

## 测试层级

1. 单元测试：纯逻辑、映射、状态机、迁移和策略。
2. 契约测试：请求路径、参数、响应映射、异常回包。
3. 集成测试：数据库、同步、窗口状态和服务适配。
4. Android UI/Smoke：入口、设置、主流程。
5. 真机验收：真实权限、真实设备与真实服务端。

## 发布门禁

- 构建、单测、lint 和目标模块测试全部通过。
- 关键接口台账没有“代码完成但未真机验收”被误标为已完成。
- 不存在明文凭据、敏感日志或未解释的权限。
- 回滚方式、版本说明、已知问题和客服/运维处理路径已准备。

## 问题闭环

每个缺陷记录复现步骤、环境、版本、日志匿名摘要、预期/实际、影响等级、负责人、修复提交和回归结果。禁止使用静默 fallback 或假成功掩盖同步、权限和执行失败。
