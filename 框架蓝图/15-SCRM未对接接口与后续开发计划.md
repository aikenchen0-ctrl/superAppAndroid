# SCRM 未对接接口与后续开发计划

## 1. 优先级

| 优先级 | 范围 | 交付标准 |
|---|---|---|
| P0 | 真实服务与真机验收 | 配置、会话读取、增量同步、文本/媒体发送、联系人和群核心操作完成真实环境记录 |
| P1 | 消息完整闭环 | 卡片模板、转发、撤回、详情补拉、媒体下载、语音转文字、收藏表情和小程序卡片接入 UI，并补齐任务终态 |
| P1 | 联系人运营 | 客户画像保存、标签创建/同步/删除、批量标签和联系人分页管理接入确认式 UI |
| P1 | 群管理 | 筛选建群、邀请/踢人、管理员、群主转让、群公告/备注/置顶/通讯录/昵称/验证等接入权限确认和审计 |
| P2 | 朋友圈扩展 | 补齐剩余 moments 路由，完善权限、批量操作和失败重试 |
| P2 | 平台与账号能力 | finder、enterprise、payments、phone、proxy、wechat-login、wechat-tools、realtime、runtime-config 等按产品范围立项 |

## 2. 统一开发流程

1. 从 `接口文档.md` 固化请求参数、响应模型、权限和错误码。
2. 在 `ScrmModels.kt` 或对应契约文件增加不可变请求/响应模型。
3. 在 `ScrmApiClient.kt` 增加明确方法或 action 路由，保留服务错误信息。
4. 用 MockTransport/fixture 验证 HTTP 方法、路径、请求体、解析和 taskId。
5. 在 UI 中加入二次确认、执行中、成功、失败和重试状态。
6. 通过 `ScrmTaskTracker` 或 `ScrmContactTaskRunner` 统一等待任务终态。
7. 使用测试账号在真机执行一次，记录脱敏请求、响应、日志和验收人。

## 3. 风险与边界

- 当前自动化测试不会访问真实 SCRM 服务，不能替代生产联调。
- POST/PUT/DELETE 不能仅凭请求对象能组装判定已完成，必须有服务端回读或人工验收证据。
- API Key、账号标识和完整聊天内容不得写入仓库文档或测试 fixture。
- 动态 action 复用会使客户端方法数与接口路由数不一，后续应维护路由覆盖表而非简单百分比。
