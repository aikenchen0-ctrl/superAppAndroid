# AI 助手与草稿协作

## 产品角色

AI 是“理解上下文、提出方案、生成草稿”的助手。发送、发布、加人、删除和任何外部写操作默认由用户确认；自动执行必须是独立、可关闭、可审计的企业级策略，不能作为默认行为。

## 草稿工作流

```text
选择上下文 -> 明示允许使用的数据 -> 生成候选 -> 用户编辑/重试 -> 预览目标与内容 -> 确认执行 -> 记录结果
```

## 输入与输出

| 输入 | 规则 |
|---|---|
| 当前会话 | 仅加载用户选择的近期消息，显示时间范围和条数。 |
| 客户资料 | 默认只读，敏感标签需按组织策略脱敏。 |
| 语音 | 先展示转写结果，用户确认后进入生成。 |
| 快捷语/模板 | 模板须注明适用场景、所有者、版本和更新时间。 |

输出分为：回复草稿、摘要、待办、风险提示、可选素材和下一步建议。每种输出必须显示生成状态、失败原因和重新生成入口。

## 草稿交互

- 未输入：提供开场、语气、意图、角色和快捷模板选择。
- 已输入：提供续写、改写、润色、缩短、扩写和风险检查。
- 多候选：使用版本标识和差异高亮，避免把 AI 修改与用户原文混淆。
- 用户可一键清空 AI 草稿，且不会删除原始输入。

## 语音和眨眼

现有实时语音和眨眼能力可以作为“开始听写/生成草稿”入口，但必须有清晰的摄像头和麦克风状态提示。眨眼不得作为隐藏确认方式，也不得在未展示预览时触发外部动作。

## 模型与成本策略

先采用单一、可观测的模型链路：配置版本、请求 ID、耗时、token/成本和失败类型。异模校验、并发 Agent 和记忆剪枝是 AIfx 的后续能力，只有在明确准确率指标、预算和人工审核点后再启用。

## 验收标准

- 用户可明确知道 AI 使用了哪些数据、生成了什么、是否已发送。
- 网络、模型或权限失败不得假装成功。
- 取消、编辑和确认后的最终内容可回溯。
