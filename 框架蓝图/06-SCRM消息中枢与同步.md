# SCRM 消息中枢与同步

## 目标

把经授权的账号、会话、消息、联系人、群聊、朋友圈和素材，以统一但可追溯的数据模型提供给 Android 悬浮工作台。消息中枢是所有 AI 建议和运营功能的事实来源。

## 当前基础与事实口径

- 仓库记录显示已覆盖约 54 个 OpenAPI 契约，涵盖消息、朋友圈、联系人、群聊、设备/任务和后台管理。
- `GET /chat/bootstrap`、`GET /chat/history`、`GET /messages/changes` 已有 Android 代码和单元契约，仍需真实设备与真实服务验收。
- 代码覆盖或单测通过不等于接口真实可用；每个接口要有后端直调、App 展示与日志三类证据。

## 同步顺序

1. Bootstrap：加载账号、会话摘要、未读数、头像和初始 sequence。
2. History：按会话与游标加载消息历史；明确消息为空与读取失败。
3. Changes：按 sequence 拉取增量、幂等合并、去重并更新检查点。
4. Realtime：只有轮询稳定、服务端具备能力且断线恢复可验证后，才引入推送通道。

## 数据一致性规则

- 所有记录含来源 ID、账号 ID、会话 ID、服务端时间、同步时间和版本/sequence。
- 本地写操作处于“待确认、已提交、成功、失败、未知”之一，未知状态不得展示为成功。
- 同一消息以稳定远端 ID 去重；无远端 ID 时使用受限的临时键并在回包后替换。
- 读取失败保留上一次可信快照，并显示其同步时间；不吞掉错误。

## 接口优先级

| 优先级 | 能力 | 目的 |
|---|---|---|
| P0 | 会话引导、历史、增量、未读、头像 | 让悬浮聊天可读、可更新。 |
| P1 | 联系人详情、客户画像、共同群、朋友圈时间线 | 支撑上下文和人工运营。 |
| P2 | 撤回、转发、实时推送、群高级管理 | 在权限和真实验收成熟后扩展。 |

## 验收台账字段

接口、环境、账号范围、请求参数脱敏摘要、后端结果、App 结果、日志位置、测试人、时间、状态、阻塞原因。凭据、完整会话内容和个人敏感信息禁止进入仓库文档。
