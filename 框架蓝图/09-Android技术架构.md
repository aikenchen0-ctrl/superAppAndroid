# Android 技术架构

## 架构原则

保留现有多模块边界，新增能力优先放在对应领域模块；UI、业务编排、平台能力和网络存储不要相互穿透。共享的是领域模型和契约，不强行共享 Android/iOS 的 UI 代码。

## 模块职责

| 模块 | 责任 | 后续方向 |
|---|---|---|
| `ubiki-core` | 手势、边缘区、领域模型和纯逻辑 | 保持 Android 无关、可单测。 |
| `ubiki-overlay` | 触控层、边缘提示、坐标与绘制 | 与无障碍控制器通过小接口协作。 |
| `ubiki-accessibility` | 无障碍服务、悬浮聊天、数据同步、AI 编排 | 按 chat、scrm、ai、data 子域继续拆分。 |
| `app` | Activity、设置、权限引导、磁贴 | 不承载复杂业务规则。 |
| `adbcore` | 可选的连接和保活能力 | 独立开关、明确失败可见。 |
| `blinkvoice-visual-sdk` | 视觉/眨眼采集 | 仅通过稳定契约暴露能力。 |

## 分层建议

```text
Compose/Activity/Overlay
        -> ViewModel/Coordinator
        -> Use Case/Policy
        -> Repository/Port
        -> OpenAPI、Room、系统服务、媒体和无障碍 API
```

UI 不直接发 HTTP；业务策略不依赖具体数据库；系统服务通过接口适配，方便单测和故障定位。

## 悬浮聊天技术要点

- 窗口生命周期由单一宿主控制，防止旋转、Activity 切换和权限变化时重复挂载。
- 消息渲染按类型注册；将只读数据、瞬态状态和样式拆开，避免集中式条件分支持续膨胀。
- 连接线用 Compose Canvas/原生绘制即可，坐标由统一状态源管理；性能不足时允许关闭装饰层。
- 网络同步使用协程、取消传播、分页和幂等合并；不在主线程执行图片加载、文件读取或数据库迁移。

## 可观测性

统一记录：模块、请求 ID、账号匿名标识、会话匿名标识、动作、耗时、结果和错误类别。日志不得包含密码、完整 URL 查询、完整消息、语音和媒体内容。Debug 诊断与生产遥测分别配置。

## 测试策略

- `ubiki-core`：手势与模型单测。
- `ubiki-overlay`：区域、坐标和视觉策略单测。
- `ubiki-accessibility`：同步契约、数据迁移、状态机和 Coordinator 测试。
- `app`：主入口、权限、设置与 smoke test。
- 真机：无障碍、悬浮窗、键盘、横屏、媒体、网络故障和服务端真实回包。
